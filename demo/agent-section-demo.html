Architecture B Demo

Kubeflow Agent Section

This prototype is running as a resource-optimized Architecture B setup: Kagent-managed agent flow, live MCP tools, Groq-backed reasoning, and Milvus retrieval for both docs and code.

Live Demo Status

  • Kagent controller, UI, tools, and agent are running in GKE.
  • Remote MCP server is accepted and serving Kubeflow retrieval tools.
  • Milvus already contains populated docs_collection and code_collection.
  • The HTTP agent API streams route decisions, tool calls, and final answers.

What Is Being Used

The prototype is aligned with Architecture B at the logic and orchestration level.

  • Kagent managed agent
  • Remote MCP server for retrieval tools
  • Milvus vector search for docs and code
  • Groq as the external OpenAI-compatible model endpoint

What Is Deferred

These pieces are intentionally minimized for the prototype so the demo stays stable on a smaller GKE budget.

  • In-cluster LLM serving with KServe
  • Istio-heavy managed ingress path
  • Full auth and production-grade policy layers
  • Persistent conversation state store

Why This Is The Best Demo Path

The expensive part of Architecture B is not the agent logic. It is the Kubernetes overhead from operator tooling and local model serving.

  • Faster responses for a live mentor demo
  • Lower RAM and CPU usage in GKE
  • Core Architecture B flow still demonstrated honestly
  • Easy path to harden later without rewriting the backend
